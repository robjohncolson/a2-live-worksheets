## Task: Explore Post-ISR Dispatch Execution (Phase 24B)

You are working on a TI-84 Plus CE ROM transpilation project. Phase 24A just unlocked the ISR dispatch gate — the IM1 handler at 0x000038 now reaches callback dispatch at 0x000710 for the first time. Your job is to explore what the ISR does post-dispatch, discover new code regions, find missing blocks, and seed them.

### Context

After Phase 24A, the ISR path is:
```
0x000038 → 0x0006F3 → 0x000704 → 0x000710 (callback dispatch)
  → 0x001713 → 0x0008BB → 0x001717 → 0x000719
  → 0x0019BE-0x001A32 (OS event loop)
  → 0x001005 → 0x00401A (new territory)
  → eventually halts at 0x0019B5
```

Two missing blocks were discovered: `0x0019B6:adl` and `0x0032D1:adl`

Test 7 (IM1 wake with shared state) now shows 63 steps, 9 dynamic targets, 2 missing blocks.

The ISR reads a callback address from RAM at 0xD02AD7. Since memory is zeroed, this returns 0x000000 — which means the callback dispatch calls into the reset vector area. With properly initialized callback tables, this would dispatch to OS event handlers (keyboard scan, LCD refresh, timer tick, etc.).

### Step 2: Explore the OS event loop (0x0019BE-0x001A32)

Add Test 12 that starts execution directly at 0x0019BE (the OS event loop) with properly set up state:
- IY = 0xD00080 (system vars base, required by OS code)
- SP = a reasonable stack (0xD40000 or wherever boot leaves it)
- IM = 1
- Run 100,000 steps with block/missing/dynamic tracing

The event loop at 0x0019BE likely checks system flags at (IY+offset) and dispatches to handlers. With no flags set, it should loop back to power-down HALT. But the blocks it VISITS on the way tell us what code regions the event loop references.

### Important context

- Memory is 16MB (`new Uint8Array(0x1000000)`) since Phase 23
- CPU registers are 24-bit (BC/DE/HL have 24-bit backing stores) since Phase 23
- The executor uses `runFrom(startAddress, startMode, opts)` three-arg signature
- `result.termination` (not `result.reason`) for exit status
- `PRELIFTED_BLOCKS` (not `blocks`) is the export name from ROM.transpiled.js
- Timer interrupts can be disabled with `timerInterrupt: false` in peripheral bus options
- The OS sets IY = 0xD00080 (system vars base). Various (IY+offset) locations are system flags.
- Block 0x000710 does: `LD HL, (0xD02AD7)` / `PUSH HL` / `CALL 0x001713`
  - 0xD02AD7 is a 24-bit callback pointer in RAM
  - 0x001713 calls the address on the stack
- The flash handler returns 0xD0 (hardware ready status). Do not change this.
- Keyboard port 0x01 returns 0xFF (no keys pressed). Do not change this.
- ROM is 4MB (0x000000-0x3FFFFF). Addresses above 0x400000 are RAM or I/O.
- `romBytes` is available as a Uint8Array — read 3-byte LE addresses as `romBytes[addr] | (romBytes[addr+1] << 8) | (romBytes[addr+2] << 16)`
