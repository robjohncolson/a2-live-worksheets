## Task: Add DD/FD/ED Prefix Handling to eZ80 Decoder

The file `TI-84_Plus_CE/ez80-decoder.js` (525 lines) already handles unprefixed opcodes and CB prefix. Your job is to add DD/FD prefix (IX/IY indexed) and ED prefix (extended instructions) handling.

### Files you MUST read first

- `TI-84_Plus_CE/ez80-decoder.js` — Read the ENTIRE file to understand the structure, helper functions, tag naming conventions, and the `decodeInstruction` export.

### Current structure

The file has:
- Helper functions: `hex()`, `signedByte()`, `readImm()`, `getImmWidth()`
- Register tables: `REGS8`, `REGS16`, `ALU_OPS`, `CONDITIONS`, `ROTATE_OPS`
- `decodeCB()` — CB prefix bit operations
- `decodeMain()` — unprefixed opcodes (0x00-0xFF except CB/DD/FD/ED)
- `decodeInstruction()` — entry point that checks for mode prefix, then dispatches

Currently, DD/FD/ED opcodes return `null`. You need to add three decoder functions and wire them in.

### What to modify

**1. Add `decodeDD_FD()` function** for IX/IY indexed instructions.

When DD or FD is the opcode:
- DD = index register is 'ix', FD = index register is 'iy'
- Check for doubled prefix: if DD followed by FD (or vice versa), consume first, second wins
- Check for DD/FD CB d op — indexed bit operations (displacement before CB opcode)
- Otherwise: most instructions mirror the main opcode table but with IX/IY replacing HL and (IX+d) replacing (HL)

Key behaviors:
- `DD 21 nn nn` → `LD IX, nn` (tag: `'ld-pair-imm'`, pair: 'ix')
- `DD 36 d nn` → `LD (IX+d), n` (tag: `'ld-ixd-imm'`, indexReg, displacement, value)
- `DD 46 d` → `LD B, (IX+d)` (tag: `'ld-reg-ixd'`, dest, indexReg, displacement)
- `DD 70 d` → `LD (IX+d), B` (tag: `'ld-ixd-reg'`, indexReg, displacement, src)
- `DD 86 d` → `ADD A, (IX+d)` (tag: `'alu-ixd'`, op, indexReg, displacement)
- `DD BE d` → `CP (IX+d)` (tag: `'alu-ixd'`, op: 'cp', indexReg, displacement)
- `DD E1` → `POP IX` (tag: `'pop'`, pair: 'ix')
- `DD E5` → `PUSH IX` (tag: `'push'`, pair: 'ix')
- `DD E9` → `JP (IX)` (tag: `'jp-indirect'`, indirectRegister: 'ix', terminates: true)
- `DD F9` → `LD SP, IX` (tag: `'ld-sp-pair'`, pair: 'ix')
- `DD E3` → `EX (SP), IX` (tag: `'ex-sp-pair'`, pair: 'ix')
- `DD 09/19/29/39` → `ADD IX, rr` (tag: `'add-pair'`, dest: 'ix', src: pair)
- `DD 23` → `INC IX` (tag: `'inc-pair'`, pair: 'ix')
- `DD 2B` → `DEC IX` (tag: `'dec-pair'`, pair: 'ix')
- `DD 34 d` → `INC (IX+d)` (tag: `'inc-ixd'`, indexReg, displacement)
- `DD 35 d` → `DEC (IX+d)` (tag: `'dec-ixd'`, indexReg, displacement)
- `DD 22 nn` → `LD (nn), IX` (tag: `'ld-mem-pair'`, addr, pair: 'ix')
- `DD 2A nn` → `LD IX, (nn)` (tag: `'ld-pair-mem'`, pair: 'ix', addr)

For register-only ops (not involving (HL) position), H→ixh/iyh, L→ixl/iyl:
- `DD 44` → `LD B, IXH` (tag: `'ld-reg-reg'`, dest: 'b', src: 'ixh')
- `DD 45` → `LD B, IXL`
- `DD 60` → `LD IXH, B`
- etc.

Half-register substitution: In the DD/FD context, when the register field is H (4) or L (5) AND the instruction does NOT use (HL) as memory operand, substitute with ixh/ixl (or iyh/iyl).

**DD/FD CB d op — indexed bit operations:**
- Byte sequence: DD CB d op (4 bytes)
- `d` is signed displacement
- `op` determines the operation (same encoding as regular CB)
- Always operates on (IX+d) or (IY+d)
- Tags: `'indexed-cb-bit'`, `'indexed-cb-set'`, `'indexed-cb-res'`, `'indexed-cb-rotate'`
- Fields: `indexRegister`, `displacement`, `bit` (for bit ops), `operation` (for rotate)

For IN0/OUT0 register mapping: ED 38=IN0 A, ED 00=IN0 B, ED 08=IN0 C, ED 10=IN0 D, ED 18=IN0 E, ED 20=IN0 H, ED 28=IN0 L. (Bits 5-3 encode register.) Same pattern for OUT0 at ED 01/09/11/19/21/29/31/39.

Wait — the actual IN0/OUT0 encoding on eZ80:
- IN0: ED + (r << 3) where r uses standard register encoding, mapped to opcodes ED 00, ED 08, ED 10, ED 18, ED 20, ED 28, ED 30, ED 38
- OUT0: ED 01, ED 09, ED 11, ED 19, ED 21, ED 29, ED 31, ED 39

Actually the standard encoding is simpler. For the ED prefix block:
- Opcodes ED 40-7F follow a pattern: bits 5-3 = register, bit 0 = IN(0)/OUT(1), bits 2-1 determine operation type
- ED 40 = IN B,(C), ED 41 = OUT (C),B, ED 42 = SBC HL,BC, ED 43 nn = LD (nn),BC
- ED 48 = IN C,(C), ED 49 = OUT (C),C, ED 4A = ADC HL,BC, ED 4B nn = LD BC,(nn)
- Pattern: (op & 0x07) determines sub-operation within each register group

Use this pattern for a compact decoder.

Replace the `return null` stubs for DD/FD and ED with calls to the new functions.

### Important: immWidth for DD/FD instructions

Indexed instructions with displacement use: prefix byte(s) + opcode + displacement + optional immediate.
The address/immediate width for LD IX, nn etc. follows the same mode/modePrefix rules as main opcodes.
