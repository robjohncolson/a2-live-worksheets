## Task: Unlock ISR Dispatch + Keyboard Interrupt Wiring (Phase 24A)

You are working on a TI-84 Plus CE ROM transpilation project. The ROM boots to power-down HALT successfully. IRQ wake works but the ISR always re-enters power-down due to a gate at block 0x000704. Your job is to unlock the OS event loop by fixing the flash port and wiring keyboard interrupts.

### The Problem (READ THIS CAREFULLY)

The IM1 handler (0x000038) dispatches through this path:

```
0x000038  EX AF, AF' / EXX / PUSH IX / PUSH IY / LD IY, 0xD00080 / JP 0x0006F3

0x0006F3  IN0 A, (0x06)     ← flash port, currently returns 0x00
          BIT 2, A           ← tests bit 2 (sets Z flag, does NOT change A)
          JR Z, 0x000704     ← taken because bit 2 of 0x00 = 0

0x000704  SET 6, (IY+27)     ← sets system flag, doesn't change A
          NOP (ED 6E)        ← doesn't change A
          CP 0xD0            ← compares A with 0xD0 — A IS STILL 0x00 from port 0x06!
          JP NZ, 0x0019B5    ← ALWAYS TAKEN → power-down. This is the blocker.
          ; falls through to 0x000710 (callback dispatch) — NEVER REACHED
```

**A is never modified between the IN0 at 0x0006F3 and the CP at 0x00070A.** The flash handler must return 0xD0 for the ISR to dispatch.

### Hypothesis

The boot sequence writes a value to port 0x06 during initialization. The current flash handler (`peripherals.js` line ~108) stores writes in `state.flash.lastWrite` but always returns `0x00`. If the OS writes 0xD0 during boot and the handler returned that value, the CP 0xD0 gate would pass.

### Step 2: Fix the flash handler

Based on Step 1 findings:

**If boot writes 0xD0 to port 0x06**: Change `createFlashHandler()` to return `state.flash.lastWrite` instead of `0x00`:

```javascript
function createFlashHandler(state) {
  return {
    read() {
      return state.flash.lastWrite;  // Was: return 0x00
    },
    write(port, value) {
      state.flash.lastWrite = value;
    },
  };
}
```

Also update the initial value: `flash: { lastWrite: 0x00 }` should stay 0x00 (before boot writes to it).

**If boot does NOT write 0xD0**: Set flash handler to return 0xD0 unconditionally after boot, OR figure out what value is needed and how to derive it.

### Step 3: Register keyboard scan port 0x01

Add a keyboard handler to the peripheral bus. Port 0x01 is used for keyboard scanning:
- Write: selects which key group to scan (bit pattern, active low)
- Read: returns which keys in the selected group are pressed (active low: 0 = pressed)

Initial implementation — no keys pressed:

```javascript
const keyboardState = { groupSelect: 0xFF, keyMatrix: new Uint8Array(8).fill(0xFF) };

register(0x01, {
  read() {
    // Return key status for selected group(s)
    // For now: 0xFF = no keys pressed
    let result = 0xFF;
    for (let g = 0; g < 8; g++) {
      if (((keyboardState.groupSelect >> g) & 1) === 0) {
        result &= keyboardState.keyMatrix[g];
      }
    }
    return result;
  },
  write(port, value) {
    keyboardState.groupSelect = value;
  },
});
```

Expose `keyboardState` through the peripheral bus return value so tests can simulate key presses:

```javascript
return {
  read, write, register, getState,
  tick, hasPendingIRQ, hasPendingNMI,
  acknowledgeIRQ, acknowledgeNMI, triggerNMI, triggerIRQ,
  keyboard: keyboardState,  // NEW — expose for key simulation
};
```

### Important context

- Memory is 16MB (`new Uint8Array(0x1000000)`) since Phase 23
- CPU registers are 24-bit (BC/DE/HL have 24-bit backing stores) since Phase 23
- The executor uses `runFrom(startAddress, startMode, opts)` three-arg signature
- `result.termination` (not `result.reason`) for exit status
- `PRELIFTED_BLOCKS` (not `blocks`) is the export name from ROM.transpiled.js
- Timer interrupts can be disabled with `timerInterrupt: false` in peripheral bus options — useful for controlled tests
- The OS sets IY = 0xD00080 (system vars base). (IY+27) at 0xD0009B is a system flag byte.
- Block 0x000710 reads a callback address from RAM at 0xD02AD7 — this will be uninitialized (0x000000) in our memory. The call to 0x001713 may fail if it tries to call the callback. That's OK for analysis — report what happens.
- The interrupt controller at 0x5000+ has rawStatus, enableMask, masked status registers. Bit 10 = keyboard. The OS may need enableMask bit 10 set for keyboard IRQs to fire.
