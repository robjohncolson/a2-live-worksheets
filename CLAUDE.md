# Algebra 2 Desk

An isolated Algebra 2 fork for LEHS sections C (Mon/Tue/Thu), D (Mon/Wed/Fri), and G (Tue/Wed/Thu/Fri), SY2026–27. Early-release Wednesdays remain meeting days.

The roster, academic ledger, receipts, transcripts, flashcards, teacher feedback, and offline recovery survive. The district grade is Assessments 50% (minimum 4), Assignments 40% (minimum 10), and Engagement 10% (minimum 10). Lesson checks are 10 points, topic assessments 100, Try-Its 2, and passed lesson decks 1 per quarter. Missing due work counts as zero after its lesson day. The alternative v3 engine retains its two-track gates.

Content is authored in `../Lesson_planning`; see `A2_FORK_PLAN.md` for the Savvas transcription and question-bank pipeline. Lessons 1-1, 1-2, 1-5 and 1-6 are published in `content/a2/`; `docs/a2-lesson-targets.md` sets the authoring order and other lessons stay unpublished until authored content is ready. The whole year is dated by the year plan in `data/a2-lesson-targets.json` (generated by `node scripts/build-a2-year-plan.mjs` from the published dates, the plan order and the closures in `desk.html`; `--check` verifies it). The Desk calendar draws unpublished planned lessons as dimmed cells and each topic's assessment day; grading only reads the published model. IXL skills per lesson are authored by IXL code in `data/a2-lesson-skills.json` and resolved by `node scripts/build-a2-lesson-skills.mjs` (writes `content/a2/lesson-skills.json` for every lesson and `supportingSkills` for published lessons; `--check` verifies); the Desk shows them on published and planned cells. `content/a2/lesson-objectives.json` holds each lesson's learning/language objectives verbatim from its packet (or the Savvas source doc in `content/a2/source-docs/` until the packet exists); the Desk strip shows the current lesson's and `node scripts/build-a2-week-objectives.mjs [--week YYYY-MM-DD]` prints the week's whiteboard copy for all three sections (HTML in gitignored `roster-local/week-objectives/`). `content/a2/day-log.json` is the day log (what landed per section and day, plus lesson resources); it decorates the calendar and never moves a due date. A teacher can close a lesson early (or late) from its Desk panel: `PUT /teacher/pacing/reflow` re-dates that section from the lesson on, using `lib/a2-year-plan.js` and `data/a2-school-year.json` (both generated/synced with the plan). After editing `data/a2-lesson-skills.json` run `node scripts/build-a2-lesson-skills.mjs` first. After editing `content/a2/lessons.json` or `data/a2-lesson-targets.json` run `node scripts/build-a2-year-plan.mjs`, `node scripts/sync-server-shared.mjs`, `node scripts/build-a2-roadmap-data.mjs` and `node scripts/build-a2-work-manifest.mjs`; after any Desk/JS/CSS/content change run `node scripts/bump-build.mjs` before committing (PWA cache). `data/ixl-algebra2-skills.json` resolves an IXL shortcut code (PS2, W5Z; IXL's permanent skill ID) to its Algebra 2 directory ID, name, strand and skill page; it is generated by `node scripts/build-ixl-skill-map.mjs` from the teacher's workbook in `data/sources/` (`--check` verifies it). Look codes up there before opening IXL; add verified skill-page URLs to the script's `KNOWN_URLS`.

Fast lessons: `docs/a2-fast-lesson-spec.md` is how a lesson is cut to the PLC's Oct 20 shape (at most two Savvas Examples chosen for the lesson-quiz items, then IXL Web Jams, then the Savvas quiz) and what each lesson produces: `../Lesson_planning/a2_<L>_fast.tex` + `.pdf` (packet on `fast-packet-template.tex`), `a2_<L>_quiz_fast.tex` + `.pdf` (short-form quiz with key), and one entry each in `content/a2/lesson-prep.json`, `content/a2/lesson-objectives.json` and `data/a2-lesson-skills.json`. Lint a packet with `python -I ../Lesson_planning/tools/check_fast_packet.py a2_<L>_fast.tex --te a2_<L>_TE.tex --quiz a2_<L>_quiz_fast.tex --ixl-map data/ixl-algebra2-skills.json --compile` (run from `../Lesson_planning`); merge draft entries with `node scripts/merge-fast-lesson-drafts.mjs <drafts-dir>`, then the skills build, `sync-server-shared`, roadmap, work manifest, `node scripts/build-lesson-tree.mjs --all` and the tests. The keep/cut in a prep entry is a proposal until its `status` line records the PLC's ruling.

Class recordings: the Class Log phone records each block and posts a lesson summary to roster-server (`school/class-log`). `node scripts/pull-class-summaries.mjs` pulls the last 30 days of Algebra 2 summaries (`--from`/`--to` for other ranges, `--dry-run` to list them) into gitignored `roster-local/class-summaries/`: one `<date>-<section>.md` per recorded block (front matter, then the Landed, Student questions, Promises made and Next prep sections) and `index.json` with those four lists for every summary. The folder is generated (never hand-edit it; rerun the pull) and stays local: the summaries quote student questions and the teacher's remarks, and this repo publishes to GitHub Pages, so they are never committed. The pull takes seconds; run it before reading. The day log stays the record of what landed; the summaries feed it (daily procedure step 1 in `CONTINUATION_PROMPT.md`). `npm run pull-summaries` is the same pull.

Nightly "Tomorrow" draft: `node scripts/draft-tomorrow.mjs [--date YYYY-MM-DD] [--section C|D|G]` writes one note per section for its next class day to gitignored `roster-local/tomorrow/<date>-<section>.md` and prints it (Do Now, Then, Quiz target, Promises / questions, Left in the packet). Deterministic, no LLM; the logic is `lib/a2-tomorrow.js`, shared with the teacher day panel's "Tomorrow (draft)" fold. Sources in order: the day log (its `lesson` for the day wins over the year plan; past days with only a `plan` count as unconfirmed evidence), `content/a2/lesson-prep.json`, `content/a2/lesson-skills.json` (the assigned skills; a code the prep only proposes is never a Do Now), `data/ixl-algebra2-skills.json`, and the section's latest Class Log summary. Teacher rule (2026-10-22): a Do Now is never a new task. It is the Jam the day's plan names, else the assigned IXL skill of the next kept example, else the first skill not yet jammed, else a kept example or the DOK 3 item not yet in the day log; the note keeps the class format (IXL skills, packet, quiz) and never adds an activity. `tools/nightly_tomorrow.ps1` runs the pull then the draft and logs to `roster-local/tomorrow/log.txt`; the Windows task `A2 Tomorrow Draft` (daily 20:30, `tools/register_tomorrow_task.ps1`) runs it. Tests: `tests/draft-tomorrow.test.js` on the synthetic tree `tests/fixtures/a2/tomorrow/` (never the real `roster-local/`).

Run `npx vitest run` at root, `npm test` from `roster-server/` (runs the legacy v3-forced suite and the district-formula suite; `npm run test:district` alone for the production formula), and `pytest tests/` at root. Named inherited failures and phase results live in `A2_FORK_BASELINE.md`.


Historical architecture and removed-feature documents are in `docs/apstats-history/`; use `A2_FORK_PLAN.md` and `A2_FORK_BASELINE.md` for the current Algebra 2 implementation.
