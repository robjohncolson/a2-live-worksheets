**Task**: Write a self-contained pure-logic block for study guide v5 (dose ladder + FRQ queue), plus a vitest suite for it.

**Context**: The study guide diagnostic (`study_guide_diagnostic.html`) currently has a v4 daily queue that picks MCQs via `pickDailyQueue(state, today, examDate)` using `ceil(remaining / days)` dose sizing. We're replacing that with a 4-tier ladder that also generates FRQ entries. See `CONTINUATION_PROMPT.md` entries 73-75 for prior context on the v4 architecture. The v4 logic block pattern is in `.v4-logic-block.js` — follow that same IIFE wrapper pattern.

**Deliverable 1**: `.v5-ladder-block.js` — an IIFE wrapped as `(function(window){ ... })(typeof window !== 'undefined' ? window : globalThis);` that publishes `window.__studyGuideV5__` with these exports:

**Constants**:

```
LADDER = [
  { tier: 0, mcq: 5,  frq: 1, label: 'Warmup',   color: 'green'  },
  { tier: 1, mcq: 7,  frq: 1, label: 'Steady',   color: 'yellow' },
  { tier: 2, mcq: 10, frq: 2, label: 'Catch-up', color: 'orange' },
  { tier: 3, mcq: 12, frq: 2, label: 'Crunch',   color: 'red'    }
]
STUDY_START_DATE = '2026-04-14'
TIER_CALENDAR_DAYS = [0, 8, 15, 21]
GATE_IDS_V5 = { 1:'U1-PC-FRQ-Q02', 2:'U2-PC-FRQ-Q02', 3:'U3-PC-FRQ-Q01', 4:'U4-PC-FRQ-Q02', 5:'U5-PC-FRQ-Q02', 6:'U6-PC-FRQ-Q01', 7:'U7-PC-FRQ-Q02', 8:'U8-PC-FRQ-Q01', 9:'U9-PC-FRQ-Q01' }
```

`TIER_CALENDAR_DAYS` index = tier; value = minimum day-of-study-period that auto-bumps to that tier.

**Pure functions** (no DOM, no fetch, no timers):

1. `daysSinceStudyStart(todayStr, startStr = STUDY_START_DATE)` returns an integer. Day 1 = start date. Use `max(1, ceil((today - start) / ONE_DAY) + 1)`.

2. `calendarTier(todayStr, startStr = STUDY_START_DATE)` returns the highest tier t (0 to 3) such that `TIER_CALENDAR_DAYS[t] <= daysSinceStudyStart(today)`.

3. `debtToTier(debt)` returns `Math.min(3, debt)`. (1 debt = tier 1, 2 = 2, 3+ = 3, 0 = 0.)

4. `computeDoseTier(state, todayStr)` returns `max(calendarTier(today), debtToTier(state.doseLadder.mcqDebt), debtToTier(state.doseLadder.frqDebt))`. Clamp to [0, 3]. Treats missing `state.doseLadder` as all zeros.

5. `tierSpec(tier)` returns the matching `LADDER[tier]` entry (or `LADDER[0]` if out of range).

6. `updateDebtFromPriorDose(state, todayStr)` MUTATES `state.doseLadder.mcqDebt` and `state.doseLadder.frqDebt`. Behavior:
   - If `state.dailyDose && state.dailyDose.date !== todayStr` (day has rolled over):
     - `mcqExpected = state.dailyDose.mcq.length`
     - `mcqDone = state.dailyDose.mcqCompleted.length`
     - `short = max(0, mcqExpected - mcqDone)`
     - `over = max(0, mcqDone - mcqExpected)`
     - `state.doseLadder.mcqDebt = max(0, (state.doseLadder.mcqDebt or 0) + short - over)`
     - Same calculation for frqDebt using `state.dailyDose.frq.length` and `state.dailyDose.frqCompleted.length`.
   - If `state.dailyDose.date === todayStr`, no-op.
   - If `state.dailyDose` is null or undefined, no-op.
   - Must be idempotent — safe to call multiple times on the same state.
   - If `state.doseLadder` is missing, initialize it to `{ tier: 0, mcqDebt: 0, frqDebt: 0 }` before the computation.

7. `unitMeanMastery(unitState)` reads `unitState.masteryState` (object keyed by loId with number values in [0,1]). Returns the arithmetic mean. Returns `0.3` if empty or missing. This reuses v3-era LO mastery data.

8. `pickDailyFrqs(state, n)` iterates units 1..9. For each unit u, compute `unitMeanMastery(state.units[u])`. Skip units where `state.units[u] && state.units[u].frqGrade` is truthy (already graded this session). Sort remaining units ascending by mastery. Take the first n. Each entry: `{ kind: 'frq', unit: <1-9>, questionId: GATE_IDS_V5[unit], formulaId: null }`. Returns an array (may be shorter than n if fewer units are eligible).

9. `pickDailyQueueV5(state, todayStr, examDateStr)` orchestrates the daily build:
   - First call `updateDebtFromPriorDose(state, todayStr)` to roll over debt from yesterday.
   - If `state.dailyDose && state.dailyDose.date === todayStr`, return it (idempotent per day).
   - Compute `tier = computeDoseTier(state, todayStr)`; `spec = tierSpec(tier)`.
   - Build MCQ side by reusing the weighted-picker logic from v4 — specifically, read `window.__studyGuideV4__.pickDailyQueue` which already does the priority + weight sort and returns `{ queue: [...] }`. BUT its dose is computed internally; since we need a fixed dose from `spec.mcq`, the easiest path is to re-implement the v4 picker loop here using v4's exported helpers (`formulaWeight`, `pickProbeForFormula`, `FORMULA_UNIT_MAP`, `touchedFormulaCount`). Copy the core loop (coverage-floor priority, weight sort, walk sorted list calling `pickProbeForFormula`) from `.v4-logic-block.js` but cap the dose at `spec.mcq`. Tag each entry with `kind: 'mcq'`.
   - Build FRQ side via `pickDailyFrqs(state, spec.frq)`.
   - Return:
     ```
     {
       date: todayStr,
       tierAtGeneration: tier,
       mcq: [...],
       mcqCompleted: [],
       frq: [...],
       frqCompleted: [],
       activeTab: 'mcq'
     }
     ```
   - Note: the caller is responsible for assigning this to `state.dailyDose`; this function does not mutate `state.dailyDose` itself (other than through the `updateDebtFromPriorDose` call which reads the old `dailyDose`).

10. `advanceDailyQueueV5(state, currentQuestionId)` — tab-aware advancement:
    - Find which pool contained `currentQuestionId` (mcq or frq).
    - Push `currentQuestionId` onto `state.dailyDose.<pool>Completed` if not already there.
    - Find the next uncompleted entry in the SAME pool. If found, return it.
    - If current pool is exhausted, check the OTHER pool for uncompleted entries. If found, return the first one AND set `state.dailyDose.activeTab` to the other pool name.
    - If both exhausted, return `null` (daily queue complete).
    - Does NOT call `setActiveProbe` — that is the render pipeline's job. Just returns the next entry or null.

11. `setActiveTab(state, tab)` sets `state.dailyDose.activeTab = tab === 'frq' ? 'frq' : 'mcq'`. No return value. Safe if `state.dailyDose` is null (no-op).
