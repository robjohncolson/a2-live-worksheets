# Study Guide — Focused Redesign Spec

_Last updated: 2026-04-13_
_Predecessor specs: `.study-guide-spec.md`, `.study-guide-spec-v2.md`, `.study-guide-spec-html.md`_

## Goal

Rebuild the student-facing surface of `study_guide_diagnostic.html` around a
single commitment: **one problem on screen at a time, with weakness visible at
a glance**. Everything else — all 9 units, all 417 probes, the entire DAG —
collapses into a quiet LO-grouped tree rail and a single "Next weakest"
button.

The machinery (BKT, probe selector, tag map, framework context, AI grading)
stays. The UI is what changes.

## Why

Today the student sees 9 unit cards, 6 probes per card, a DAG panel per card,
and a focus synthesis panel per card. That's high cognitive load, the DAG
visualization is decorative (not actionable), and the AI's best output
(`focusLessons[].loIds`, `suggestedAction`) lands as static text the student
can't click. The loop doesn't close.

The goal of this redesign is **total diagnostic coverage in the most painless,
efficient manner**. Painless = one thing at a time. Efficient = BKT picks the
next probe, AI judgement drives what's weak, curriculum_render is one click
away for remediation.

## Shape of the new UI

Three-pane layout at desktop widths, stackable at narrow widths.

```
┌──────────────────────────────────────────────────────────────────────┐
│  Header: Study Guide  ·  [Paper / Night]  ·  [Export] [Import]       │
├─────────────────┬────────────────────────────────────┬───────────────┤
│                 │                                    │               │
│  LO Tree Rail   │        Active Probe (ONE)          │  Remediation  │
│  (left)         │        (center)                    │  (right)      │
│                 │                                    │               │
│  U1 ▓▓▓░  72%   │   ┌──────────────────────────┐     │  Lesson 5.2   │
│   VAR-1.A 68%   │   │                          │     │  Sampling     │
│   VAR-1.B 80%   │   │   Q: Which of the        │     │  distribution │
│   ...           │   │   following sampling     │     │  of the mean  │
│                 │   │   distributions...       │     │               │
│  U2 ▓▓░░  54%   │   │                          │     │  [Open in     │
│   DAT-1.D 40%◀  │   │   (A) ○  (B) ○           │     │   curriculum] │
│   ...           │   │   (C) ●  (D) ○           │     │               │
│                 │   │                          │     │  AI says:     │
│  U5 ▓▓▓▓ 82%    │   │   [ Check ]              │     │  "You're      │
│   ...           │   └──────────────────────────┘     │   mixing up   │
│                 │                                    │   σ and σ/√n" │
│  [Next weakest] │   Tagged LOs: VAR-6.A, VAR-6.B     │               │
│                 │                                    │               │
└─────────────────┴────────────────────────────────────┴───────────────┘
```

- **LO Tree Rail (left):** one line per unit with an aggregate bar, expanded
  to show per-LO bars. Each LO row is clickable: click → load a probe for that
  LO into the center. The node with the current probe's primary LO is
  highlighted (◀). Sort order within a unit: lowest mastery first. Priority
  tints from focus synthesis bleed into the unit row (`high`/`medium`/`low` →
  red/amber/green dot).
- **Active Probe (center):** exactly one MCQ or FRQ. MCQ shows prompt +
  options + Check. FRQ shows prompt + textarea + Grade. No adjacent questions.
  After Check, the card reveals feedback inline (correct/incorrect for MCQ;
  E/P/I + `matched`/`missing` for FRQ) and exposes a "Next" button.
- **Remediation panel (right):** context-sensitive. When the probe is unsolved,
  shows the primary LO's framework text. When the probe has been checked with
  feedback, shows the AI's `suggestedAction` (if set) as a button linking to
  `../curriculum_render/index.html?u=N&l=M`, plus a shorter synthesis blurb.
- **Header:** theme toggle, export/import. No per-unit controls; the tree is
  the navigation.

Narrow-screen behavior: rail collapses to a "Weak spots" disclosure at the top,
remediation collapses to a "Why this matters" disclosure at the bottom, center
stays dominant.

## Color themes

Two themes, chosen from the header. Stored in `localStorage` under
`apStatsStudyGuideDiagnostic.theme`.

### Paper (default)
- Background: `#f7f2e8` (warm off-white)
- Text: `#2a2520`
- Accent: `#7a4a1f` (muted brown)
- LO bar track: `#e2d6c0` / fill interpolates red→amber→green
- Card: `#ffffff` with 1px `#d8ccb0` border, 0.5rem radius
- Font: Georgia / serif for prompts, system sans for UI chrome

### Night
- Background: `#14171c`
- Text: `#e4e7ec`
- Accent: `#6ca6ff`
- LO bar track: `#222833` / fill interpolates red→amber→green (desaturated)
- Card: `#1a1f27` with 1px `#2a3140` border
- Font: same as Paper

Mastery colors keep semantic meaning across themes. Theme switch is
instantaneous (CSS variables only).

## How AI judgement actually drives behavior

This is the loop-closing part. Every existing AI output becomes a signal, not
a text blob.

| AI output | Currently | New role |
|---|---|---|
| FRQ `score` (E/P/I) | Displayed | Displayed + feeds BKT via focus synthesis |
| FRQ `matched`/`missing` | Displayed | Displayed (remediation panel) |
| FRQ `feedback` | Displayed | Displayed (remediation panel) |
| Focus `focusLessons[].loIds` | Displayed | **Drives BKT downward updates**; each loId in the focus list gets `updateMastery(false)` applied once |
| Focus `focusLessons[].lesson` | Displayed | Builds the curriculum_render deep link |
| Focus `suggestedAction` | Displayed | Label on the "Open in curriculum" button |
| Focus `priority` (high/mid/low) | Displayed | Tints the unit's row in the rail |
| Focus `overallSummary` | Displayed | Shown in remediation panel above the suggested action |

### FRQ → BKT, concretely

1. Student grades an FRQ (existing flow).
2. `runFocus(unit)` is called with the FRQ grade.
3. Focus synthesis returns `focusLessons[]`.
4. For each `loId` in every `focusLessons[i].loIds`, call
   `BKT.updateMastery(masteryState[loId], false)` once and write back.
5. Rail re-renders. "Next weakest" now points at whatever bubbled up.

No new `GATE_LO_COVERAGE` table needed — the AI is effectively the LO lookup.
If focus synthesis returns empty `focusLessons`, BKT is untouched and the
rail stays the same.

### Deep links to curriculum_render

Pattern (confirmed via `handleURLNavigation` in
`../curriculum_render/index.html:10527`):

```
../curriculum_render/index.html?u={unit}&l={lesson}
../curriculum_render/index.html?q={questionId}   // e.g., U4-L2-Q01
```

The "Open in curriculum" button in the remediation panel uses the
unit/lesson form. If a specific source question is useful (probe came from
`U4-L2-Q01`), the `?q=` form is preferred because it scrolls to the exact
question.

## What gets removed

- `renderDagPanel` function and its callers. Gone.
- `.dag-panel`, `.dag-svg-wrap`, `.dag-legend` CSS blocks. Gone.
- Per-unit cards with all probes visible simultaneously. Replaced by the LO
  tree rail and the single-probe center pane.
- Unit-level "Check all / Focus / Export per unit" buttons. Replaced by a
  global header.

The `lib/dag-renderer.js` module **stays on disk** so tests keep passing, but
nothing in `study_guide_diagnostic.html` loads it. It becomes dead code we can
delete in a follow-up once the new layout ships.

## What gets kept

- `lib/bkt.js` (unchanged)
- `lib/probe-selector.js` (unchanged — still powers "Next weakest")
- `lib/question-lo-tagger.mjs` and `data/question-lo-map.js` (unchanged)
- `data/dag-topology.js` (still consumed by ProbeSelector for edge awareness,
  just not rendered)
- `ai-grading-prompts-study-guide.js` (extended, not replaced — focus synthesis
  prompt is fine as-is; the change is **how we consume its output**)
- Export/import (extended to cover the new schema)

## State schema migration (v3)

Current `apStatsStudyGuideDiagnostic.v2` structure:

```js
{
  schemaVersion: 2,
  units: {
    1: { mcqAnswers, mcqResults, frqAnswer, frqGrade, focus, masteryState },
    ...
  }
}
```

New `apStatsStudyGuideDiagnostic.v3`:

```js
{
  schemaVersion: 3,
  theme: 'paper' | 'night',
  activeProbe: { unit, questionId, source: 'manual' | 'next-weakest' | 'lo-click' } | null,
  units: {
    1: {
      mcqAnswers, mcqResults, frqAnswer, frqGrade,
      focus: { ... },            // unchanged shape
      masteryState: { [loId]: number },   // unchanged, plus FRQ downward updates
      priority: 'high' | 'medium' | 'low' | null  // cached from last focus run
    },
    ...
  }
}
```

### Migration

- v2 → v3: add `theme = 'paper'`, add `activeProbe = null`, cache
  `priority = null` per unit. masteryState, mcqAnswers, frqAnswer,
  mcqResults, frqGrade all copy forward.
- Unknown version → fresh v3 default.

## New / changed symbols in `study_guide_diagnostic.html`

### Add
- `renderTreeRail()` — renders the left rail from `topology.units` sorted by
  mastery ascending, with per-unit aggregate + per-LO rows. Clickable.
- `renderActiveProbe()` — renders the single center card from
  `state.activeProbe`. Picks MCQ or FRQ template based on question type.
- `renderRemediation()` — renders the right panel from the active probe's
  primary LO and the cached focus output.
- `pickProbeForLo(unit, loId)` — returns the best probe for an LO: prefers
  untouched questions tagged with loId, falls back to the probe selector.
- `pickNextWeakest()` — scans all units, finds the lowest-mastery LO that has
  an un-answered probe, calls `pickProbeForLo`.
- `setActiveProbe(unit, questionId, source)` — updates state, re-renders
  center + remediation, marks the rail row.
- `applyFrqFocusToBkt(unit, focus)` — the FRQ → BKT bridge described above.
- `applyTheme(theme)` — sets `data-theme` on `<html>`, saves to localStorage.
- `buildCurriculumLink(unit, lesson, questionId?)` — URL builder.

### Remove
- `renderUnit(unit)` (replaced)
- `renderUnits()` (replaced)
- `renderDagPanel(unit)`
- Anything that references `window.DagRenderer`

### Keep / lightly edit
- `buildProbes`, `buildProbesLegacy`, `ensureMasteryState`, `loIdsForQuestion`,
  `tagEntry`, `unitTopology` — stay.
- `runFocus(unit)` — stays, with one added line:
  `applyFrqFocusToBkt(unit, focus)` after the focus result is saved.
- `makeDefaultState`, `normalizeState`, `getUnit` — extended for v3 fields.

## CSS approach

All colors moved to CSS variables on `:root[data-theme="paper"]` and
`:root[data-theme="night"]`. Layout uses CSS grid for the three-pane
desktop view and a media query flip to stacked at `max-width: 900px`.

Key variables:
```
--sg-bg, --sg-bg-card, --sg-text, --sg-text-dim,
--sg-accent, --sg-border, --sg-bar-track,
--sg-mastery-low, --sg-mastery-mid, --sg-mastery-high
```

No JS-driven color math. The mastery bar uses a three-color linear gradient
background with a `clip-path` or `width` to show the fill.

## Tests

New `tests/study-guide.test.js` cases (additive — keep existing v2 tests
passing until v3 ships, then migrate):

1. Active-probe state: `makeDefaultState()` includes `activeProbe: null`,
   `theme: 'paper'`, per-unit `priority: null`.
2. Theme toggle persists across a reload simulation.
3. `pickNextWeakest` returns an untouched probe tagged with the lowest-mastery
   LO given a seeded `masteryState`.
4. `pickProbeForLo` prefers an untouched probe tagged with the given LO over
   a probe that's already answered.
5. `applyFrqFocusToBkt` applies one `updateMastery(false)` per unique loId in
   a focus result with two `focusLessons` entries sharing an LO.
6. `buildCurriculumLink(5, 2)` returns `../curriculum_render/index.html?u=5&l=2`.
7. Rail rendering: given a seeded masteryState where U2 is weakest, the rail
   DOM renders U2 as the first unit.
8. Remediation panel: given a focus result with `suggestedAction`, the
   remediation panel renders a button with that label and an href pointing at
   the right lesson.
9. Schema migration: a v2 state object migrates cleanly into v3 with no data
   loss.
10. Structural negative test: `renderDagPanel` / `DagRenderer` are no longer
    referenced by the HTML.

Runtime smoke (`lib/study-guide-runtime.test.js`) stays as-is — it tests the
modules, not the HTML shell.

## Out of scope

- Touching `lib/dag-renderer.js` — leave it as dead code for now.
- Any server-side changes (Railway, `/api/ai/grade`).
- Adding a new `GATE_LO_COVERAGE` table.
- A "review mode" that replays previously-answered probes. Could come later.
- Multi-theme beyond Paper / Night (no light purple, no high contrast, no
  sepia — resist the feature creep).
- Keyboard shortcuts. Nice-to-have, separate phase.

## Acceptance criteria

- `study_guide_diagnostic.html` loads and shows exactly one probe at a time.
- Clicking an LO in the tree rail changes the center probe to one tagged with
  that LO.
- "Next weakest" button changes the center probe to one for the lowest-mastery
  un-answered LO across all units.
- Grading an FRQ runs focus synthesis, and the LOs in `focusLessons[].loIds`
  have their BKT mastery reduced immediately (visible in the rail).
- The remediation panel's "Open in curriculum" button opens
  `../curriculum_render/index.html?u=N&l=M` in a new tab and lands on the
  right lesson.
- Theme toggle works and persists across reload.
- Export/import round-trips v3 state with all fields intact.
- All existing `tests/study-guide.test.js` DAG/BKT structural tests either
  pass or are replaced by equivalent v3 tests. All `lib/*.test.js` unchanged
  and passing.
- No references to `renderDagPanel` or `DagRenderer` in the HTML.
