## Goal

Replace v3's tree-rail ("every weak LO across every unit, sorted by mastery") with a focused **daily queue** that shows a small, deadline-aware number of problems per session and surfaces formula work via student-friendly formula *names* (not framework skill IDs).

## Why v3 is wrong (user feedback, evening 2026-04-13)

1. Rail shows every weak LO in every unit at once — overwhelming, reads as "lots of work."
2. Units are sorted by ascending mastery, so the rail opens with Unit 6 for no reason a student can see.
3. Every skill shows 30% mastery by default on first load — reads as "you're failing" before any evidence exists.
4. Formula practice is externalized to Formula Defense instead of being woven into the diagnostic.
5. Framework codes (`VAR-3.D`, `UNC-1.B`) are student-visible in rail + remediation and create noise.

## v4 design contract

### 1. Daily queue engine

The left pane becomes **Today's queue** — a short list of probes the student works through one at a time. Everything else (the v3 "see all weak LOs" view) collapses behind a disclosure.

- **Dose formula**: `dose = clamp(ceil(remainingFormulas / daysLeft), 3, 12)` where
  - `daysLeft = max(1, daysBetween(today, examDate))`
  - `examDate = '2026-05-07'` (hardcoded constant `AP_EXAM_DATE` in the shell, easy to change)
  - `remainingFormulas` = count of formulas in the **active pool** (core + regular + power + support = 81) that still need a touch before the coverage floor is reached, OR that have mastery < `MASTERY_THRESHOLD` once the floor is met
  - `MASTERY_THRESHOLD = 0.75` (tunable constant in shell)
- **Today's dose** is computed once per calendar day per device and stored in `state.dailyDose = { date: 'YYYY-MM-DD', queue: [...], completed: [...] }`. If `state.dailyDose.date !== today()`, the queue is regenerated.
- **Per-probe completion** is tracked in `state.dailyDose.completed` so the student can refresh the page mid-session and the queue picks up where they left off.
- **When the queue is empty** ("Done for today" state), show a congratulatory panel with a button to "Pull tomorrow's queue early" (manually triggers regen for the next day's dose using the next-day daysLeft).

### 2. Weighted picker (for filling the queue)

Given a dose of N probes, pick N formulas using this weight:

```
weight(formula) = examWeight(unit(formula)) × tierMultiplier(formula.tier) × (1 - currentMastery(formula))
```

- **examWeight(unit)** — midpoint of the AP Course Framework range for that unit (from `frameworks.js`):
  - U1: 0.19, U2: 0.135, U3: 0.06, U4: 0.15, U5: 0.095, U6: 0.135, U7: 0.14, U8: 0.035, U9: 0.035
  - Hardcode these midpoints in a `UNIT_EXAM_WEIGHTS` constant in the shell (not parsed from `frameworks.js`, so they survive if framework copy changes).
- **tierMultiplier(tier)**:
  - `core`: 4
  - `regular`: 3
  - `power`: 2
  - `support`: 1
- **currentMastery(formula)**:
  - If the formula has been answered in a session, its latest BKT value (initialized from `BKT.DEFAULT_PARAMS.pInit`).
  - If untouched, use the BKT init value (`pInit = 0.3`) under the hood — but surface it as "untested" in the UI (see §5).
- **Selection algorithm**:
  1. Build the candidate list — every formula in `ap-stats-cartridge.js` (via `formula-probe-map.json` + `formula-probe-supplement.js` merged).
  2. Compute weight for each candidate.
  3. If any candidate is below the coverage floor (never touched), promote it to the top of the weight-ordered list regardless of weight (coverage floor takes priority).
  4. Sort weight-desc; take the top `dose` picks.
  5. For each pick, resolve to a specific probe via `pickProbeForFormula(formulaId)` (see §3).
- **Tie-breaking**: deterministic — sort by `(−weight, formulaId)` so the same day produces the same queue on refresh.

### 3. Coverage floor

Before any formula can be repeated, **every core+regular formula (18+14 = 32)** must have been touched at least once.

- "Touched" = the student has answered (correctly or incorrectly) at least one probe tagged to that formula within the current `state.dailyDose` lifetime OR in historical `state.touchedFormulas`.
- Persist `state.touchedFormulas = { formulaId: { firstTouchedAt: 'YYYY-MM-DD' } }` so touches carry across days.
- Coverage floor check: `coreAndRegularTouched >= 32`.
- Until the floor is met, the picker **must** include at least one untouched core/regular formula per dose (unless all 32 are already touched).

### 4. Formula-name labels (not framework IDs)

**Never render `VAR-3.D` or similar in the student UI.** Framework IDs stay in state (for BKT wiring), but all labels use formula `action` strings from `ap-stats-cartridge.js`:

- Rail card heading: `"SD of p-hat"` (formula `action`), not `"VAR-3.D · 30%"`.
- Remediation kicker: `"Sample Standard Deviation (s)"` (formula `action`), not `"Primary LO · UNC-1.C"`.
- When a probe covers multiple formulas, show the primary formula name only.

The shell will load `ap-stats-cartridge.js` as a data file (copied or symlinked to `data/ap-stats-cartridge.js` in `follow-alongs/`) and expose it as `window.AP_STATS_CARTRIDGE`. The cartridge source of truth stays in `tmux-trainer/` — we copy a snapshot, don't depend on cross-repo paths.

### 5. Drop the 30% default — show "untested" as a neutral dot

BKT still runs under the hood with `pInit = 0.3`, but the UI:

- Shows an empty dot `○` (or "untested" pill) instead of "30%" for any formula/skill the student hasn't yet answered.
- Only renders a percentage once `state.touchedFormulas[formulaId]` exists.
- Color coding applies only to touched formulas: red (<0.5), yellow (0.5–0.74), green (≥0.75).

### 6. Natural unit order in any "see all" disclosure

Under the "See all units" disclosure (details/summary), show units 1 → 9 in numerical order. No mastery sort. Within a unit, formulas are grouped by domain in the order defined in `ap-stats-cartridge.js` (not re-sorted).

### 7. Single active probe center pane (unchanged from v3)

The middle pane keeps its v3 shape: one probe card, prompt, MCQ radios, Check button, feedback, Next button. Behavior:

- Clicking Check: mutates BKT mastery for all LO IDs tagged to that question, **also** records a touch for the formula the queue assigned (via `state.dailyDose.queue[i].formulaId`), re-renders rail + remediation.
- Clicking Next: advances to the next probe in `state.dailyDose.queue`, marking the current one `completed`.
- When queue is empty, renders the "Done for today" panel described in §1.

### 8. Remediation pane (right, minor updates)

The remediation pane still uses framework lesson info but swaps the kicker and heading:

- Kicker: formula `action` string (e.g., "Standard Error of p-hat"), not `"Primary LO · VAR-3.D"`.
- Heading: lesson topic from `UNIT_FRAMEWORKS[unit].lessons[lesson].topic`.
- Body: reasoning text from the supplement probe IF the active probe is a supplement entry, else the skills list from the framework.
- Footer: "Open in curriculum" deep link (unchanged from v3).

### 9. Supplement probe integration

The shell must load `data/formula-probe-supplement.js` alongside the main curriculum:

- For main-curriculum entries, the picker uses `formula-probe-map.json` to resolve `formulaId → questionId[]`.

### Migration rules

- If `raw.schemaVersion === 4`: pass through (with field-level normalization).
- If `raw.schemaVersion === 3`: copy all existing fields forward. Set `touchedFormulas = {}`, `dailyDose = null`. The next render of the queue will regenerate it.
- If `raw.schemaVersion === 2`: run v2→v3 migration first (existing code), then v3→v4.
- If schemaVersion is unrecognized or missing: `makeDefaultState()`.

`init()` should:
1. Try to load `apStatsStudyGuideDiagnostic.v4` first.
2. Fall back to `apStatsStudyGuideDiagnostic.v3` → migrate → save to v4 key → continue.
3. Fall back to `apStatsStudyGuideDiagnostic.v2` → migrate to v3 → migrate to v4 → save → continue.
4. Otherwise `makeDefaultState()`.

**Import (HTML file upload)**: recognize `data-state-id="sg-state-v4"`, `sg-state-v3`, or `sg-state-v2` and migrate forward.

## Functions to add/change

### New functions

- `loadCartridge()` — reads `window.AP_STATS_CARTRIDGE`, builds `FORMULAS_BY_ID`, `FORMULAS_BY_TIER`, `FORMULAS_BY_UNIT` lookup maps. Called once in `init()`.
- `formulaUnit(formulaId)` — maps a formula to its primary unit using a hardcoded `FORMULA_UNIT_MAP` (hand-authored, see below).
- `formulaName(formulaId)` — returns `cartridge.commands[id].action` (student-friendly name).
- `computeDailyDose(today, examDate)` — returns `clamp(ceil(remaining/days), 3, 12)`.
- `daysLeft(today, examDate)` — `Math.max(1, Math.ceil((examDate - today) / MS_PER_DAY))`.
- `formulaWeight(formulaId, masteryByFormula)` — returns `examWeight × tierMult × (1 - mastery)`.
- `pickDailyQueue(state, today, examDate)` — main picker. Returns `Array<{ formulaId, questionId, unit, lesson, tier }>`.
- `pickProbeForFormula(formulaId, state)` — resolves a formula to a specific probe, preferring untouched probes. Uses the formula-probe-map for main curriculum + supplement entries' `formulaId` field. Returns `null` if no probe exists.
- `formulaMastery(formulaId, state)` — reads `state.touchedFormulas[formulaId].lastMastery`, falls back to `BKT.DEFAULT_PARAMS.pInit` if untouched.
- `touchedFormulaCount(state, tier)` — counts touched formulas for the coverage floor.
- `recordFormulaTouch(formulaId, correct, state)` — updates `state.touchedFormulas[formulaId]` on a check.
- `renderQueuePane()` — replaces `renderTreeRail()`. Shows the queue, skip button, done-for-today panel, see-all disclosure.
- `renderSeeAllDisclosure()` — builds the collapsed "See all 81 formulas" view.
- `renderDoneForToday()` — congratulatory panel when queue is empty.

### Changed functions

- `renderActiveProbe()` — heading shows formula name; on Check, calls `recordFormulaTouch`; Next button advances through `state.dailyDose.queue`.
- `renderRemediation()` — kicker uses `formulaName(activeProbe.formulaId)`.
- `init()` — loads cartridge + supplement; migrates state; calls `renderQueuePane()` + `renderActiveProbe()` + `renderRemediation()`.
- `setActiveProbe(unit, questionId, source, formulaId)` — extended with `formulaId`.
- `makeDefaultState()`, `normalizeState()` — add `touchedFormulas`, `dailyDose` fields + migration.

### Removed / no longer called

## Risk notes

- **Cartridge drift**: `data/ap-stats-cartridge.js` is a snapshot of `tmux-trainer/ap-stats-cartridge.js`. If upstream gains/removes formulas, the study guide won't see it until someone re-copies. Add a `data/ap-stats-cartridge-VERSION.txt` with the copy date so we know when it was last synced.
- **Exam-date hardcoding**: `AP_EXAM_DATE = '2026-05-07'` is hardcoded in the shell. When AP 2027 prep starts, update the constant in one place.
- **Missing probe for a formula**: If `pickProbeForFormula` returns `null` for a selected formula (e.g., a formula with 0 probes in both main curriculum and supplement), the picker must skip it and pull the next candidate rather than inserting a `null` into the queue. Supplement covers all 81 gaps currently, so this should never trigger in practice — but defensive coding required.
- **BKT re-initialization after migration**: v3 state has `masteryState` per unit keyed by LO ID. v4 picker uses per-formula mastery. The mapping formula → LO is indirect (via formula-probe-map → questionId → loIds). For v4, `formulaMastery(formulaId)` reads from `state.touchedFormulas[formulaId].lastMastery` directly — it does *not* try to reach through `state.units[u].masteryState`. This means v3 students' BKT progress doesn't migrate to v4 formula mastery; they start "untested" on the queue. Acceptable — the rail already felt wrong, a reset is a clean slate.
- **Content correctness of U6-L4-QS1 rewrite**: verified by hand (1068 calculation). Distractor E (385) uses `(0.1)(0.9)·(1.96/0.03)²` which equals `0.09 × 4267.11 = 384.04 ≈ 385`, so that's mathematically sensible too.

## Notes on what NOT to build into v4

- **No new LO tagging.** Formula→probe mapping is the source of truth for v4.
- **No Formula Defense embedding.** Deep-link only.
- **No server-side daily-dose persistence.** Per-device `localStorage` is fine.
- **No streak tracking, no gamification.** Just the queue + counter.
- **No framework-ID rendering.** Anywhere. The only place framework IDs appear is inside `state.units[u].masteryState` for BKT's sake.
