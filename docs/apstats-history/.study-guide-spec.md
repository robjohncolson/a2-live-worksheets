# Spec: AP Stats Diagnostic Study Guide Worksheet

**Goal**: Build a single-file HTML diagnostic worksheet that helps students identify which AP Statistics units/lessons they need to review. Nine "gate" questions (one per unit, free-response, AI-graded via DeepSeek through the existing Railway framework). Each gate that is scored `I` (Incorrect) opens a drill-down panel with lesson-level MC probes; each probe that the student gets wrong reveals links to the remediation resources available for that lesson.

| 3 | U3 | `U3-PC-FRQ-Q01` | Unit 3: Collecting Data | Experimental design, random assignment vs random selection, scope of inference |

If a gate has `requiresGraph: true`, show a note "*(This question may reference a figure from the College Board FRQ. If you need it, ask your teacher.)*" — do not attempt to render graphs beyond simple tables.

## Probe selection algorithm (client-side, runs at load)

For each unit `U{n}` where the gate scored `I` or the student manually opens the drill-down:

```js
function buildProbesForUnit(unitNumber) {
  const unitPrefix = `U${unitNumber}-L`;
  // All MC questions in this unit, grouped by lesson
  const mcByLesson = {};
  for (const q of EMBEDDED_CURRICULUM) {
    if (q.type !== 'multiple-choice') continue;
    if (!q.id.startsWith(unitPrefix)) continue;
    const m = q.id.match(/^U\d+-L(\d+)-Q\d+/);
    if (!m) continue;
    const lesson = parseInt(m[1], 10);
    (mcByLesson[lesson] ||= []).push(q);
  }
  // Sort lessons ascending, pick first MC from each lesson, cap at 6 probes
  const lessons = Object.keys(mcByLesson).map(Number).sort((a, b) => a - b);
  const probes = [];
  for (const lesson of lessons.slice(0, 6)) {
    const first = mcByLesson[lesson].sort((a, b) => a.id.localeCompare(b.id))[0];
    probes.push({ lesson, question: first });
  }
  return probes;
}
```

Each probe renders as:
- The prompt text
- The choices as radio buttons (`attachments.choices` is an array of `{key, value}`)
- `attachments.table` rendered as an HTML `<table>` if present
- `attachments.image` rendered as `<img>` with `attachments.imageAlt`/`imageCaption` if present (images live at `../curriculum_render/{image}` — try that path; broken image is acceptable for MVP)
- A "Check" button that compares the selected radio to `answerKey` (exact match → correct, else incorrect)
- On incorrect: append a **Resource Card** for that lesson

**Probes are NOT AI-graded.** They're multiple choice — client-side string comparison against `answerKey` is the whole grading logic.

Use `target="_blank"` on all resource links so the diagnostic page stays open while the student reviews.

## Grading threshold rules

| Gate result | Drill-down panel | Visual badge | Copy |
|---|---|---|---|
| `E` | Hidden (collapsible header says "✓ Unit passed — click to review anyway") | Green | "Strong — you nailed the unit-level synthesis." |
| `P` | Collapsed but visible header: "Review these if you want to strengthen this unit" | Yellow | `result.feedback` from API |
| `I` | **Auto-expanded** with "⚠ Focus here" header | Red | `result.feedback` from API |

The enrichment pass that u6_lesson1-2 does (upgrading strong `P` → `E`) — port it verbatim into the study guide: if `result.score === 'P' && result.missing?.length === 0`, upgrade to `E` with a "Nice work" message before storing.

## `ai-grading-prompts-study-guide.js` — structure

Unlike the existing per-unit rubric files (which hand-craft `expectedElements` for each question), this file uses a **generic AP-rubric prompt template** that passes through the unit context + full question text to DeepSeek. DeepSeek already knows AP Statistics.

```js
// ai-grading-prompts-study-guide.js
window.LESSON_CONTEXT_SG = `
This is a diagnostic study guide for AP Statistics. Each question is a College Board Progress Check FRQ covering the synthesis of one unit. Grade as the AP Exam would grade it — partial credit is allowed but the student should be addressing every part of the question with statistically correct reasoning. Be strict about statistical vocabulary (population vs sample, parameter vs statistic, interval vs point estimate, etc.) but forgiving of minor arithmetic slips as long as the method is right.
`;

window.UNIT_TITLES_SG = {
  1: 'Unit 1: Exploring One-Variable Data',
  2: 'Unit 2: Exploring Two-Variable Data',
  3: 'Unit 3: Collecting Data',
  4: 'Unit 4: Probability, Random Variables & Probability Distributions',
  5: 'Unit 5: Sampling Distributions',
  6: 'Unit 6: Inference for Categorical Data — Proportions',
  7: 'Unit 7: Inference for Quantitative Data — Means',
  8: 'Unit 8: Inference for Categorical Data — Chi-Square',
  9: 'Unit 9: Inference for Quantitative Data — Slopes',
};

window.GATE_IDS_SG = {
  1: 'U1-PC-FRQ-Q02',
  2: 'U2-PC-FRQ-Q02',
  3: 'U3-PC-FRQ-Q01',
  4: 'U4-PC-FRQ-Q02',
  5: 'U5-PC-FRQ-Q02',
  6: 'U6-PC-FRQ-Q01',
  7: 'U7-PC-FRQ-Q02',
  8: 'U8-PC-FRQ-Q01',
  9: 'U9-PC-FRQ-Q01',
};

window.buildReflectionPromptSG = function(unitNumber, fullQuestionText, studentAnswer) {
  const unitTitle = window.UNIT_TITLES_SG[unitNumber] || `Unit ${unitNumber}`;
  return `You are grading an AP Statistics Progress Check Free-Response Question for ${unitTitle}.

## Question (full text as it appears on the College Board PC-FRQ):
${fullQuestionText}

## Student's answer:
${studentAnswer}

## Grading instructions:
Grade using the AP Exam rubric convention:
- E (Essentially Correct): Addresses every part of the question with statistically correct reasoning and correct vocabulary. Minor arithmetic slips are OK if the method is right.
- P (Partially Correct): Addresses most parts but has one substantive gap — e.g., skips a part, uses wrong vocabulary, confuses parameter/statistic, or has a method error in exactly one part.
- I (Incorrect): Missing multiple parts, fundamental conceptual errors, or wrong procedure.

Respond in JSON:
{
  "score": "E" | "P" | "I",
  "feedback": "1-2 sentence summary of what they did right and what's weakest",
  "matched": ["parts they handled correctly, as short bullet phrases"],
  "missing": ["parts they skipped or got wrong, as short bullet phrases"],
  "suggestion": "optional: one sentence of specific advice"
}`;
};

window.getRubricSG = function(unitNumber) {
  return {
    unitNumber,
    unitTitle: window.UNIT_TITLES_SG[unitNumber],
    gateId: window.GATE_IDS_SG[unitNumber],
  };
};
```

### JS responsibilities (in the inline `<script>`)

1. **On DOMContentLoaded**: iterate `window.GATE_IDS_SG`, look up each in `EMBEDDED_CURRICULUM`, render a gate card with:
   - Unit title + gate ID badge
   - Prompt text (strip the `"Show all your work..."` boilerplate prefix before displaying — match `/^Show all your work[^.]*\.[^.]*\.\s*/` and strip)
   - Any `attachments.table` rendered as an HTML table
   - A `<textarea id="sg-u{n}-answer">` for the student's response
   - A placeholder for feedback (`<div id="sg-u{n}-feedback">`)
   - A collapsed drill-down container (`<div id="sg-u{n}-drill" hidden>`)

2. **Grade button handler**: iterate gate IDs, for each textarea.value.length > 20, call a local `gradeGate(unitNumber, questionId, answer)` that:
   - Pulls the full prompt from `EMBEDDED_CURRICULUM`
   - Builds the grading prompt via `window.buildReflectionPromptSG(unitNumber, fullPrompt, answer)`
   - POSTs to `${window.RAILWAY_SERVER_URL}/api/ai/grade` with `{scenario: {topic: 'AP Statistics Diagnostic', questionId, lessonContext: window.LESSON_CONTEXT_SG}, answers: {answer}, prompt}`
   - Awaits JSON response, applies the enrichment-pass upgrade rule from u6_lesson1-2, stores in `gradingState` Map
   - Calls `renderGateResult(unitNumber, result)` which sets the badge, feedback block, and drill-down visibility per the threshold rules above
   - If `result.score === 'I'` (or `'P'` and the student clicks the drill-down header): calls `buildProbesForUnit(unitNumber)` and renders probes

3. **Probe rendering + grading**: as described in the probe algorithm section. On wrong answer, append the Resource Card using the path conventions above. Use `target="_blank"` on links.

4. **localStorage persistence** (key `apStatsStudyGuideDiagnostic.v1`):
   ```js
   {
     savedAt: ISO string,
     studentName, studentPeriod, studentDate,
     answers: { "sg-u1-answer": "...", ... },
     grades: { "sg-u1-answer": { score: "I", feedback: "...", matched: [], missing: [] }, ... },
     probeAnswers: { "U3-L4-Q01": "B", ... },
     drillsOpened: [3, 5, 8]
   }
   ```
   - Save on every textarea input (debounced 300ms) and on grade/probe/drill state change.
   - Restore on DOMContentLoaded, hydrating textareas, grade badges, probe selections, and drill visibility.

5. **Question IDs for Railway submission**: Submit each gate's answer to `/api/submit-answer` with `{questionId: 'SG-U${n}-GATE', answer, metadata: {score}}` so the aggregate drawer works on the server. Probes submit as `SG-U${n}-L${l}-Q${n}` for class-wide tracking. Wrap these calls in try/catch and swallow network errors — failing to hit Railway should not break the diagnostic.

6. **Aggregate drawer**: Skip for MVP. Do not port the focus-following drawer. (A class-wide heatmap is phase 2.)
