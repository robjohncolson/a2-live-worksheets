# TI-84 Trainer V3 — CEmu Primary + Native State Machine

**Goal**: Students interact with a real CEmu-emulated TI-84 Plus CE. The native port runs behind the scenes as a keystroke validator and state machine. ROM loads from Supabase, cached permanently. Virtual keypad matches the physical calculator's color scheme exactly.

---

## Topology

```
┌──────────────────────────────────────────────────────┐
│  Student clicks virtual key                          │
│                                                      │
│  ┌────────────────┐       ┌────────────────────────┐ │
│  │ Native State   │       │ CEmu WASM              │ │
│  │ Machine        │       │ (real ROM execution)   │ │
│  │                │       │                        │ │
│  │ "Is this the   │──yes─→│ pressKey() → LCD       │ │
│  │  right key?"   │       │ renders real screen    │ │
│  │                │       │                        │ │
│  │ "No, wrong"────│──────→│ (blocked, not sent)    │ │
│  │  show feedback │       │                        │ │
│  └────────────────┘       └────────────────────────┘ │
│                                                      │
│  Native port NEVER renders to LCD canvas.            │
│  CEmu ALWAYS renders to LCD canvas.                  │
│  Native state machine tracks: current screen,        │
│  expected next key, wizard field state.               │
└──────────────────────────────────────────────────────┘
```

**Native port's ONLY job**: validate keystrokes and track state. It answers:
- What screen are we on?
- What is the next correct key?
- Was the student's key press correct or wrong?
- What feedback message should we show?

**CEmu's ONLY job**: execute the real ROM and render the LCD.

## ROM Loading — Supabase Bucket

### Current flow (broken UX)
1. Student opens trainer
2. File picker dialog: "Select your ROM"
3. Student has to find ROM.rom on their computer
4. ROM loads into IndexedDB

### Target flow (seamless)
1. Student opens trainer
2. ROM auto-downloads from Supabase bucket (first visit only)
3. Cached in browser — never downloaded again
4. CEmu boots immediately

### Implementation

```
Supabase bucket: ti84-trainer-assets (private or signed URLs)
File: ROM.rom (4MB)

Load sequence:
  1. Check IndexedDB for cached ROM
  2. If found → boot CEmu immediately
  3. If not → fetch from Supabase bucket URL
     → store in IndexedDB
     → boot CEmu
  4. Show progress bar during first download ("Downloading calculator firmware… 4MB")
```

**Caching strategy**: Store the ROM in IndexedDB (same as current bridge.js). Add a version key so we can bust the cache if the ROM changes. The ROM never changes (OS 5.8.2.0029), so this is effectively permanent cache.

**URL approach**: Either:
- Public bucket with CORS headers (simplest)
- Signed URL generated by a Supabase edge function (more control)
- The ROM is copyrighted TI firmware, so signed URLs with short expiry are safer

### Config

```javascript
const SUPABASE_ROM_URL = '<AP_SUPABASE_PROJECT_URL>/storage/v1/object/public/ti84-trainer-assets/ROM.rom';
// or signed URL endpoint:
const SUPABASE_ROM_ENDPOINT = '<AP_SUPABASE_PROJECT_URL>/functions/v1/get-rom-url';
```

This replaces the file picker. The ROM button in the UI becomes unnecessary — ROM loads automatically. Keep a small "ROM" status indicator (green dot when cached, spinner when downloading).

## Calculator Reset on New Problem

Every time the student starts a new walkthrough or switches procedures:

```javascript
async function startWalkthrough(procedureId) {
  // 1. Reset CEmu to home screen
  await bridge.prepareHome();    // sends CLEAR CLEAR CLEAR CLEAR to CEmu

  // 2. Reset native state machine to home
  native.reset();

  // 3. Seed list data if the procedure needs it
  if (procedure.assumeDataIn) {
    await seedListData(procedure, problem);
  }

  // 4. Sync: both CEmu and native are now on HOME screen
  // Key sequence starts from a known state
}
```

The `prepareHome()` already exists in bridge.js — it sends 4x CLEAR to CEmu. The native `reset()` snaps back to home state. Both are now synchronized.

For data-dependent procedures (1-Var Stats, histogram, etc.):
- Type the sample data into L1/L2 via CEmu key presses before starting
- OR pre-seed via the ROM's list editor if the data is long
- The native state machine also gets `setList('L1', data)` to stay in sync

## Virtual Keypad — Exact Color Match

The virtual keypad must visually match the physical TI-84 Plus CE (EZ-Spot/Teacher Pack model from 84plusCE.webp).

### Color Palette (from photo)

```css
:root {
  /* Calculator body */
  --calc-body: #4a4d52;           /* dark charcoal/graphite */
  --calc-bezel: #f5c518;          /* yellow EZ-Spot bezel around LCD */

  /* Key colors */
  --key-function: #3a3d42;        /* y=, window, zoom, trace, graph — near-black */
  --key-2nd: #5ba4cf;             /* 2nd key — light blue */
  --key-alpha: #6fbf4a;           /* alpha key — bright green */
  --key-dark: #3a3d42;            /* mode, del, x,t,θ,n, stat, math, apps, prgm, vars, clear */
  --key-trig: #3a3d42;            /* x⁻¹, sin, cos, tan, ^, x², etc. */
  --key-number: #e8e8e8;          /* 0-9 — white/light gray */
  --key-operator: #c0c0c0;        /* ÷, ×, −, +, enter — medium gray */
  --key-dpad: #c8c8c8;            /* D-pad arrows — silver/light gray */
  --key-on: #3a3d42;              /* on key — dark */

  /* Label colors */
  --label-primary: #ffffff;        /* main key text — white */
  --label-2nd-fn: #5ba4cf;        /* 2nd function labels above keys — blue */
  --label-alpha: #6fbf4a;         /* alpha labels on keys — green */
  --label-number: #000000;         /* number key text — black */

  /* LCD */
  --lcd-bg: #ffffff;               /* CE has white backlit LCD, not green */
  --lcd-bezel: #f5c518;           /* yellow surround */
}
```

### Key Layout Grid

The virtual keypad should match the physical layout zones:

```
Zone 1 — Function row (5 keys, near-black, white labels):
  [y=] [window] [zoom] [trace] [graph]
  Yellow 2nd labels above: stat plot, tblset, format, calc, table

Zone 2 — Modifier row + D-pad:
  [2nd(blue)] [mode] [del]          [D-PAD]
  [alpha(green)] [x,t,θ,n] [stat]  [cross arrows]

Zone 3 — Command row (5 keys, dark):
  [math] [apps] [prgm] [vars] [clear]

Zone 4 — Trig/math row (5 keys, dark):
  [x⁻¹] [sin] [cos] [tan] [^]

Zone 5 — Operators row:
  [x²] [,] [(] [)] [÷]

Zone 6-8 — Number pad (white keys, black text):
  [log]  [7] [8] [9] [×]
  [ln]   [4] [5] [6] [−]
  [sto→] [1] [2] [3] [+]

Zone 9 — Bottom row:
  [on] [0] [.] [(-)] [enter]
```

### Key Styling Details

Each key should show:
- **Main label**: center, white text (or black for number keys)
- **2nd function label**: above the key (not on the key), blue text, smaller font
- **Alpha label**: right side of key, green text, smaller font

The D-pad should be styled as a circular pad, not individual square keys — matching the silver circle on the physical calculator.

### Key Highlighting

When the trainer highlights the next correct key:
- **Guided mode**: the correct key pulses/glows (yellow border animation)
- **Recall mode**: no highlight (student must remember)
- **Wrong key**: brief red flash on the pressed key
- **Correct key**: brief green flash

### Responsive Sizing

The calculator should be roughly proportional to the real thing:
- LCD takes up ~40% of the height
- Keypad takes up ~60%
- Keys are touch-friendly (minimum 44px tap target on mobile)
- Whole calculator fits in the right panel of the trainer layout

## Supabase Setup

1. Create bucket `ti84-trainer-assets` in your Supabase project
2. Upload `TI-84_Plus_CE/ROM.rom` to the bucket
3. Set CORS policy to allow your deployment domain
4. Add the bucket URL to the trainer config

If using signed URLs (recommended for copyrighted firmware):
- Create edge function `get-rom-url` that generates a 1-hour signed URL
- Trainer calls this on first load, then caches the ROM bytes permanently
- Even if the signed URL expires, the cached ROM is already in IndexedDB
