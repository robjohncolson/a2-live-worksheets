## Confirmed and fixed

### 1. A hand-edited deck row crashed the server on `GET /teacher/decks`

`deckStats` did `items.map(item => item.id)` on `card_decks.items` straight from the database.
Migration 0046 only checks `jsonb_typeof(items) = 'array'`, and its header invites hand edits in
the SQL editor, so `items = [null, "stray", ...]` is reachable. The throw happened outside the
route's `try`, in an Express 4 `async` handler: the request hung and Node raised an unhandled
rejection, which exits the process (roster-server has no `process.on('unhandledRejection')`).
Every Desk load of the Rehearsal line would have re-crashed the Railway service until the row was
fixed. Reproduced with a probe (process exit, `TypeError: Cannot read properties of null`) and by
the new test, which fails with "Unhandled Rejection" without the fix.

Fix (`roster-server/card-decks.js`, `deckFromRow`): non-object entries are dropped when a row is
read, for the phone GET and the teacher GET alike. Test: `tests/card-decks.test.js`
"a hand-edited items array with a non-object entry is served without that entry, not a crash".

## Checked and clear

- **No class-log post or deck result can change a grade.** `a2.deck_results`, `a2.card_decks`,
  `a2.class_summaries`, `a2.observer_card_outcomes`, `a2.schedule_overrides`,
  `a2.schedule_days_off`, `a2.device_health*` are read and written only by their own modules; no
  grade, ledger, rollup or pacing module names them (grep over `roster-server/*.js`). The
  schedule overrides feed the Desk health strip only (`lib/class-log-health.js`), never
  `lib/a2-year-plan.js` or the due-date model.
- **Every `/teacher/*` route in scope runs `requireTeacher`** (`teacherAuth` middleware in each
  module, 403 on failure, `Cache-Control: no-store`). Every `/class-log/*` route runs
  `checkClassLogToken` before any body is parsed (mounted before the app-wide parser, verified in
  `server.js` order and the `*-app.test.js` files).
- **`CLASS_LOG_TOKEN` is compared timing-safe** (SHA-256 of both sides, then `timingSafeEqual`).
- **Every write is validated first:** deck PUT through `validateDeckPut` (card uuid, 8-14 items,
  ids, types, lengths, acyclic `after`, step minutes, model, timestamp); deck results through
  `validateResults`; summaries, overrides, days off, health pings and outcomes through their rule
  modules; U+0000 refused with a 400 everywhere a text or jsonb column is written. The RPC input
  is the validated array; the database adds the `course`, `grade`, `jsonb_typeof` checks and the
  unique keys.
- **`a2.put_card_decks` is atomic.** One PostgREST call is one statement, the function body is
  one transaction, and any `raise` (missing card, bad input, constraint) rolls back every deck.
  Cards are locked `for share` in a first pass (a concurrent delete waits), existing deck rows
  `for update`, and the insert uses `on conflict (card_id) do update`, so two first pushes for the
  same card cannot both fail. The suite's "is one transaction" test runs the real function in
  PGlite.
- **Bad input never 5xxs.** Array query params (`?date[]=`, `?date=a&date=b`, `?section[]=`),
  non-object bodies (`null`, `[]`, a string), wrong field types, fractional integers, bad or
  out-of-range timestamps, duplicate ids and cyclic `after` all answer 400 with a one-line
  reason; oversized bodies 413; storage failures 503 without details. Parser errors inside
  `createApp` are the short `{ok:false,error:'bad_json'}` from the app-wide handler.

## Plausible, not confirmed (no change made)

1. **Teacher key compare is `===`.** `requireTeacher` compares `x-teacher-secret` with
   `TEACHER_KEY` using `===` (not constant time), and also accepts `?token=` in the query
   string. Pre-existing and teacher-accepted (comment in `teacher-auth.js`); noted only.
2. **Deck result `section` is phone-supplied.** `POST /class-log/deck-results` stores the body's
   `section` (1-16 chars) without comparing it with the card's own section; the body's `date` is
   shape-checked and then replaced by the card's date. The Desk stats do not group by section,
   so this is a data-quality gap, not a grade or auth one.
3. **A timestamp without a zone is read in server-local time.** `optionalTimestamp` accepts
   `2026-10-22T10:00:00` (no `Z`/offset) and `Date.parse` treats it as local time. Railway runs
   UTC and the phone sends offsets, so no observed effect; a stricter regex would pin it.
4. **Express 4 async handlers have no global safety net.** The fix above removes the one
   reachable throw found; any future throw outside a route's `try` would again hang the request
   and exit the process. A `process.on('unhandledRejection')` logger or an Express 5 upgrade
   would make this a 500 instead. Out of scope for a minimal change.
5. **The roster-name check in `draft-card-decks.mjs` is silent when no roster CSV is present.**
   `loadRosterFirstNames` returns `[]` if `roster-local/roster-view-*.csv` is missing (a fresh
   checkout, CI), so a deck naming a student would pass validation and be committed to the
   tracked `content/a2/card-decks/`. The prompt tells the model never to name a student; a
   warning when the roster is absent would close it.
6. **`GET /class-log/decks` returns both courses' decks for the date.** The phone filters by
   course; no student data is in a deck, so this is bandwidth, not exposure.
7. **Route-local body limits are moot behind the app-wide parser.** `PUT /teacher/decks` (512 KB)
   and `PUT /teacher/cards` (2 MB) sit behind the 8 MB app-wide `express.json`, so their own
   limits only apply in tests. Validation still caps 20 decks x 14 items, so the practical body
   is far smaller; noted only.
8. **`DELETE /teacher/decks` keeps the results.** By design (0046 header: results outlive a
   deleted deck so the Desk keeps history); a re-pushed deck with different item ids will show
   `missed` only for ids it still has (`deckStats` drops unknown ids). Documented behaviour.
